# 🏥 台灣醫療報告申請與實體紙本匯入指引 (Hospital Report Guide)

當病患面臨跨院看診、尋求第二意見諮詢，或需要進行跨科別健康整合管理時，向醫院申請紙本病歷與檢驗報告複製本是拿回「健康資料自決權」最徹底的物理真值。

> **💡 阿喜伯的實踐故事：**
> 阿喜伯（多發性骨髓瘤患者）為了在北部尋求第二意見諮詢，需要將在新竹某醫院的就醫報告整理出來。他手拿著厚厚一疊新竹醫院影印出來的紙本病理切片報告與檢驗單，照著本指引使用手機掃描 App 轉為 PDF，安全地存入本地健康助理中，在接下來的求診中起到了決定性的溝通作用。

---

## 🎯 1. 目的 (Objective)

引導使用者與照護者主動、有策略地前往各大醫院申請完整的紙本醫療報告與原始影像，克服跨院就醫時醫療資訊散落、格式不一的物理高牆。並引導使用者如何透過手機拍照/掃描將其數位化，安全歸檔至本地 PHR 資料庫中。

---

## 📜 2. 醫療報告申請指引與實務攻略 (Acquisition Spec)

### ⚖️ 2.1 法規依據
依據 **中華民國醫療法第 71 條** 規定：
> *「醫療機構應依病人要求，提供病歷複製本，不得無故拖延或拒絕；其所需工本費，由病人負擔。」*
病患本人、或持病患親筆委託書之眷屬代理人，皆有權利要求醫院提供完整之病歷複製本，院方無權拒絕。

### 📋 2.2 去醫院要申請什麼？（詳細項目建議）

為了讓本地 AI 助理能精準提取，前往醫院病歷室或掛號櫃檯申請時，請指名要求以下項目：

1.  **完整出院病摘 (Discharge Summary)**
    *   *要求細節*：必須包含「住院經過」、「主訴」、「手術/處置紀錄」、「出院診斷（帶有 ICD-10 碼）」及「出院後醫囑與追蹤計劃」。
    *   *規費與時程*：每張約 20 元。通常在出院時或掛號櫃檯隨到隨辦（約 30 分鐘）。
2.  **病理切片診斷報告 (Biopsy/Pathology Report)**
    *   *要求細節*：必須要求「病理報告全文與免疫染色（IHC）明細」，不能只拿簡短診斷。這對確認癌症期別與基因突變至關重要。
    *   *規費與時程*：每份約 50-200 元。需掛號原看診科別由醫師開立，或直接至病歷影印專區櫃檯申請（約 1-3 天）。
3.  **檢驗報告單 (Laboratory/Lab Reports)**
    *   *要求細節*：必須要求「帶有參考值範圍（Reference Range）與檢驗單位」的完整檢驗數值單（如血液生化、腫瘤標記等）。
    *   *規費與時程*：每張約 10-20 元。直接至影印櫃檯隨到隨辦。
4.  **醫學影像光碟 (DICOM Image CD/DVD)**
    *   *要求細節*：拷貝 CT, MRI, PET-CT 的原始影像幅（DICOM 格式），並要求附帶「影像醫學報告（Radiology Report）」。
    *   *規費與時程*：每張光碟約 200-500 元。至影像拷貝專用櫃檯當場燒錄（約 20-40 分鐘）。

## 📸 3. 拍照與掃描成 PDF 放入目錄指引 (Digitization Spec)

取得紙本資料後，請依循以下規格將其數位化，以提供 OCR 與 AI 最佳的辨識品質：

### 3.1 影像拍攝與掃描規格
*   **光線均勻**：避免白熾燈直射反光。建議在自然光充足的室內，或將檯燈調至側面以防止紙張光澤反光。
*   **字體清晰與解析度**：拍照時相機應與紙張保持平行，解析度設定在 300dpi 以上（中階手機的標準相機皆可達到）。
*   **頁面對齊**：邊緣應對齊，避免傾斜超過 5 度。
*   **多頁合併**：**強烈建議使用手機掃描 App**（如 Microsoft Lens、Adobe Scan、vFlat 等）將多頁的報告（如一份 3 頁的出院病摘）連續掃描，並匯出為「單一多頁 PDF 檔」。
*   **物理移送**：將產出的多頁 PDF 或多張 JPG 圖片，傳送到電腦並直接放入 `data/inbox/` 目錄中。

---

## 🧠 4. AI 影像與文字萃取程序 (Agentic Ingestion Procedure)

當 Agentic AI 面臨使用者放入 `inbox/` 的 PDF 檔案或照片時，應遵循以下步驟進行推理與容錯解讀：

*   **判別來源並呼叫 OCR 引擎**：若是多張圖片，自動觸發圖片合成為 PDF，並移至 `data/raw/` 定錨。執行 OCR 引擎保留表格物理邊界。
*   **醫療手寫字與英文簡寫解讀 (Medical Parsing)**：台灣病歷多以英文書寫並夾雜拉丁文醫療簡寫（如 `QID` 一日四次、`PO` 口服）。AI 必須將簡寫翻譯成標準的中文用法。對於手寫紅字等模糊處，應提醒使用者手動核對。
*   **多頁順序錯亂推理 (Page Reconciliation)**：若發現 OCR 讀出的頁碼順序與實體檔案不符，AI 應依據文本中「第 X 頁/共 Y 頁」或排版特徵重新進行排序重組後，再交給 FHIR 映射器。

### 💻 實踐 Script 範本與除錯指引 (Scratch Scripts & Debug)

專案在 [`utils/pdf_processor.py`](../utils/pdf_processor.py) 中部署了一個圖片合成 PDF 腳本，解決使用者無法批次合併多張照片的痛點。

#### ⚙️ 正常運作指令
當使用者在 `data/inbox/` 放入了 `page1.jpg`, `page2.jpg`，在終端機中執行：
```bash
python3 utils/pdf_processor.py AFU_004 biopsy_report
```
*系統會自動將圖片合成為 `202X-XX-XX_AFU_004_biopsy_report_[HASH].pdf`，移至 `data/raw/clinical_reports/` 並自動刪除原 inbox 圖片。*

#### 🛠 簡單除錯指引 (Debugging Guide)

1.  **Pillow 庫遺失 (ModuleNotFoundError)**：
    *   *狀況*：系統未安裝 Pillow 影像處理套件。
    *   *處置*：在 terminal 中執行 `pip install Pillow` 進行安裝。若在完全離線環境下，可利用 macOS 內建的 `sips` 工具或 Automator 將圖片轉為 PDF，再手動搬移歸檔。
2.  **圖片旋轉導致合成後方向錯誤**：
    *   *狀況*：手機拍照時的 EXIF 方向屬性導致合成後的 PDF 頁面轉了 90 度。
    *   *處置*：修改 `pdf_processor.py` 中的影像載入段落，加入 `ImageOps.exif_transpose` 來校正方向：
        ```python
        from PIL import ImageOps
        img = Image.open(img_path)
        img = ImageOps.exif_transpose(img) # 自動依 EXIF 轉正
        ```
