# 🏥 全民健保健康存摺資料取得與解析實踐指南 (My Health Bank Guide)

本指南旨在為台灣民眾與 Agentic AI 提供一個多層次的健康存摺（健保快易通）資料「取得-解析-入庫」之自救對位指南。

> **💡 阿喜伯的實踐故事：**
> 阿喜伯每次去診所和健保特約藥局拿慢性處方箋，回家後都會用手機進入健保快易通 App，或者用電腦讀卡機登入網頁，把最新的用藥與檢驗紀錄手動另存或複製。照著本指南「極簡三支柱匯入法」的建議，阿喜伯沒有花費大把時間去匯入幾百筆無關的感冒流水帳，而是集中精力在「多發性骨髓瘤」的化療藥與「B型肝炎」的抗病毒藥物，以極低的心力維持了他個人主權資料庫的精準與高度活性。

---

## 🎯 1. 目的 (Objective)

在缺乏醫院端開放 API 與健保署直接介接的限制下，引導使用者使用各種可行、無門檻的物理手段，將個人的健保就醫、用藥、手術及檢驗資料「化整為零」地安全匯入本地端 SQLite 資料庫中，以漸進建構方式拼裝出完整的全人生健康履歷。

---

## 🗺 2. 多層次資料取得指引 (Acquisition Levels)

系統建議使用者依據以下優先級，採取不同的物理取得方式：

### 🟢 Level 1：健康存摺網頁版「另存網頁」HTML (健全度：極高)
*   **取得方法**：
    1. 使用電腦，搭配「行動自然人憑證」或「健保卡 + 讀卡機」登入 [衛生福利部中央健康保險署 - 健康存摺全球資訊網](https://myhealthbank.nhi.gov.tw/)。
    2. 點選「就醫與用藥資訊」或「檢驗檢查資料」，切換至您欲匯入的表格頁面（如用藥紀錄、最近就醫紀錄）。
    3. 在瀏覽器任意空白處按滑鼠右鍵，選擇 **「另存新檔 (Save Page As)」**，保存類型選擇 **「網頁，完整 (Webpage, Complete)」**，取得一個 `MyHealthBank.html` 檔案與同名的 `MyHealthBank_files` 資料夾。
    4. 將 HTML 檔案（及資料夾）直接拖入本地的 `data/inbox/` 目錄中。

### 🟡 Level 2：網頁表格直接複製文字 (健全度：高)
*   **取得方法**：
    1. 同樣登入健康存摺網頁版。
    2. 用滑鼠拖曳選取整個表格內容，按 `Ctrl + C` 複製。
    3. 在電腦上建立一個全新的純文字檔，貼上（`Ctrl + V`）這些文字。
    4. 將該純文字檔（命名為 `web_copied.txt`）丟入 `data/inbox/` 目錄。

### 🟠 Level 3：快易通手機 App 匯出「健康存摺 PDF」 (健全度：中)
*   **取得方法**：
    1. 打開手機「全民健保快易通」App，進入「健康存摺」。
    2. 點選「申請健康存摺 PDF 匯出」，輸入密碼後將產生的 PDF 發送至信箱，或儲存至本地端。
    3. 將 PDF 檔案拖入 `data/inbox/` 目錄。

## 🧠 3. AI 資料萃取程序 (Agentic Ingestion Procedure)

當 Agentic AI 偵測到收件箱有新檔案時，應遵循以下步驟進行推理與容錯解讀：

*   **格式研判與雜訊清理**：若是 HTML 另存檔案，先尋找同名 `_files` 資料夾，調用解析程式去除 `<nav>`、廣告等網頁雜訊 DOM 節點。若是純文字複製檔，檢查 Tab（`\t`）字元重組表格陣列，對齊錯位。
*   **民國日期轉西元**：健康存摺的就醫日期格式多為民國年（如 `115/05/20`）。AI 必須將民國年前三碼（`115`）加 `1911` 轉換為西元年（`2026-05-20`），並格式化為 ISO 8601 時間戳寫入。
*   **欄位語意對位與代碼轉譯**：對齊表頭語意，例如將 `藥品名稱` 對應為 FHIR 的 `MedicationRequest` 藥品文字；若有 10 碼健保代碼（如 `BC24333100`），將其寫入 FHIR 藥物代碼系統中。
*   **異常推論與容錯解決**：若處方中缺失用法（如一日幾次），AI 應查詢資料庫過往對同一藥物健保碼的用藥歷史並在 `meta_data` 中備註，或將其列入 **`Active Probing Checklist`** 待與病患確認；若比對出重複的「就醫日期 + 院所 + 藥物」資料則自動拋棄，避免資料庫臃腫。

## 📋 4. 極簡病況自理匯入與三支柱做法 (The Three Pillars of Personal Ingestion)

對於面臨慢性病、重大急症或癌症長期維持治療的病患（例如多發性骨髓瘤阿喜伯），醫院病歷和健康存摺中的資料量往往極其龐大，若要求病患或家屬每次看診都將所有的「交易流水帳」完整複製或匯入系統，不僅操作門檻極高，也容易造成使用者的資訊焦慮。

本手冊提倡**「極簡病況自理三支柱匯入法」**。實踐證明，病患**不需要**與醫院複雜系統對接，只要將以下 **核心三支柱資料** 匯入本地庫，系統即可對病人的病況建立 100% 的基本認識，並產出精確的個人化照護、三向用藥引導與門診溝通卡：

### 4.1 第一支柱：🏥 重大住院與手術報告 (Hospital & Discharge Reports)
*   **資料意義**：住院病歷摘要、出院病摘、手術紀錄或病理診斷報告是病人病況的「物理定錨點」。
*   **系統認識**：匯入此類文件能讓本地 AI 助理迅速定錨核心診斷（如多發性骨髓瘤）、重大臨床事件與日期（住院日期）、以及重大醫療處置（如自體周邊血液幹細胞移植），建立患者病情的基本時間軸骨架。

### 4.2 第二支柱：💊 目前用藥與用藥改變資訊 (Active Medications & Changes)
*   **資料意義**：當前正在服用的藥物，以及用藥變更歷史（如停藥、改藥、調整劑量）。
*   **系統認識**：藥物處方代表了醫療團隊當前的治療策略。透過將「出院帶藥」與「健保用藥紀錄」貼入本地端，AI 助理能自動比對出長期用藥的「狀態清單」，並在偵測到用藥異動時，啟動三向引導迴路，協助追溯起因與規劃後續副作用監控（如 Statin 類藥物的肝腎毒性與 CPK 監測）。

### 4.3 第三支柱：📊 當前與重要歷史指標 (Current & Historical Vital Indexes)
*   **資料意義**：反映病情控制與器官代謝安全的關鍵檢驗數值。
*   **系統認識**：病患無須導出成百上千項的檢驗明細，僅需將與當前疾病最直接相關的核心指標歷史值（例如多發性骨髓瘤的 IgG 電泳、WBC、PLT、GFR/Creatinine、HbA1c 等）匯入系統。AI 助理會將這些指標與「住院/手術事件」及「用藥改變時間軸」進行交叉對位，以最清晰的視覺化趨勢呈現用藥療效與代謝安全性。

## 🧠 5. 客製化希望清單與增量差分更新機制 (Wishlist & Incremental State)

為了配合「極簡自理三支柱」的日常實踐，系統採取了增量狀態更新方法論：

### 5.1 長期用藥「狀態清單」 vs. 「交易流水帳」
*   **傳統流水帳**：每次領慢連箋，重複的藥名天數都重複匯入，導致資料庫臃腫。
*   **狀態清單法**：每個規律用藥在資料庫中只有一筆主紀錄，動態更新其「開始服藥日（Start Date）」、「當前劑量」與「停藥/調整日（End Date）」，一目了然。

### 5.2 客製化「希望清單 (Wishlist)」優先級
引導病患依據優先級篩選拉取健康存摺的內容：
1.  **🔴 優先級 1：核心療效與用藥防護網**：僅拉取與當前診斷直接相關的癌症指標與主要藥物，進行高頻率增量更新與對齊。
2.  **🟡 優先級 2：重大病史與就醫軌跡**：僅在發生「住院、手術、移植、調整用藥」等重大事件時才需拉取。
3.  **🟢 優先級 3：代謝安全監控指標**：如肝腎功能、血脂、血糖。每半年至一年拉取一次最新值即可。

### 5.3 AI 差分詢問機制
當病患貼上精簡的健保用藥資料時，AI 助理會自動比對新舊紀錄，並主動提示詢問：
*   *「阿喜伯，我看到您這次的新處方多了立普妥，請問這是從何時開始固定服用的嗎？」*
*   *「這次處方中沒有看到胃莫潰，請問是醫師幫您停藥了嗎？」*
透過這種簡單的「是/否」差分問答，病患就能以極低的心力維持個人 PHR 資料 100% 的精準度。

### 💻 實踐 Script 範本與除錯指引 (Scratch Scripts & Debug)

系統在 [`utils/nhia_html_parser.py`](../utils/nhia_html_parser.py) 部署了一個乾淨的 Python 解析腳本。

#### ⚙️ 正常運作指令
在終端機中，使用者或 AI 可以直接執行以下命令，將另存的 HTML 表格轉換為乾淨的 TSV：
```bash
python3 utils/nhia_html_parser.py data/inbox/MyHealthBank.html
```

#### 🛠 簡單除錯指引 (Debugging Guide)
1.  **編碼錯誤 (UnicodeDecodeError)**：
    *   *狀況*：若遇到網頁編碼非標準 UTF-8。
    *   *處置*：在 `nhia_html_parser.py` 的第 42 行，調整為 `errors='ignore'` 或改用 `encoding='cp950'` 讀取。
2.  **抓不到特定表格 (抓出 0 個 table)**：
    *   *狀況*：網頁表格可能嵌套在特殊的 `<iframe>` 或是使用了全新的 class 屬性。
    *   *處置*：修改 `nhia_html_parser.py` 中的 `_parse_with_bs4`，使用 Chrome F12 審查表格元素，將：
        `soup.find_all('table')`
        修改為：
        `soup.find_all('table', class_='my-table-class')`。

### 🧹 本地去識別化脫敏腳本 (Local Data Scrubber)

為了方便開發與除錯，我們提供了一個本地端運行的脫敏腳本 [`utils/nhia_data_scrubber.py`](../utils/nhia_data_scrubber.py)。它不依賴任何外部雲端服務，100% 離線運行。

#### 執行去識別化指令：
```bash
python3 utils/nhia_data_scrubber.py data/inbox/MyHealthBank.html -o data/inbox/MyHealthBank_scrubbed.html -s -14
```

#### 脫敏轉換規則：
*   **直接識別符**：姓名置換為 `王小明`；身分證置換為 `A123456789`；健保卡號置換為 `000012345678`；電話置換為 `0912-345-678`。
*   **間接識別符**：醫療院所名稱模糊化為 `區域醫院A`；醫護人員姓名置換為 `醫療人員`。
*   **時間平移 (Date Shifting)**：就醫日期依照 `-s` 參數平移天數做平移，完全模糊化看診時間，但保留精確的相對時間間隔。
