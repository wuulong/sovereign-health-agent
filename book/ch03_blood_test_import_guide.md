# 🩸 健保健康存摺血液檢查結果複製匯入與明細整合實踐指南 (Blood Test Import Guide)

本指南旨在解決從台灣「健康存摺」網站複製貼上血液檢查結果時，因網頁前端寬度限制導致項目名稱或結果值被「`...`」截斷的痛點。本手冊定義了標準的手動自救步驟、AI 整合比對演算法以及資料生命週期規範。

> **💡 阿喜伯的實踐故事：**
> 阿喜伯在健保快易通網頁版上複製他的血液檢驗報告時，發現多發性骨髓瘤的關鍵療效指標 `Beta-2 Microglobulin` 被截斷成了 `Beta-2 Microglo ...`，而電泳文字也看不完整。阿喜伯的兒子照著本指南「兩階段自救與匯入工作流」的引導，先貼上主表，再點開網頁上的詳細資訊欄位複製明細，存成 `details` 檔案。在一鍵匯入後，本地端助理便自動透過模糊演算法將兩者對齊，在資料庫中成功拼裝出了無截斷的完整檢驗數值，使隨後生成的病程趨勢圖完全正確。

---

## 🎯 1. 痛點與挑戰 (The Truncation Challenge)

由於健康存摺「檢驗檢查資料」網頁表格欄位極多且無官方下載 API，多數使用者採用滑鼠直接拖曳選取、複製貼上（`Ctrl+C` / `Ctrl+V`）的方式，將資料提供給本地端去識別化與匯入腳本。
然而，這種簡單做法存在一個先天缺陷：**較長字串會被網頁介面截斷**。
*   *項目名稱截斷*：例如將 `Beta-2 Microglobulin` 截斷成 `Beta-2 Microglo ...`，將 `free kappa/lambda ratio` 截斷為 `free kappa/lamb ...`。
*   *結果描述截斷*：例如將蛋白電泳（Electrophoresis）的詳細文字截斷成 `Serum pro ...`。

為了在維持「複製貼上」極簡操作的同時，又能取得 100% 完整的醫學指標，系統設計了 **「主表匯入 + 關鍵明細二階段貼上與多源對合（Merge & Stitch）流程」**。

---

## 🗺 2. 兩階段自救與匯入工作流 (Two-Stage Workflow)

當使用者發現匯入的血液報告中含有被截斷的欄位時，請遵循以下操作步驟：

```
[步驟一：複製主表] ─────> 寫入 data/inbox/IN_YYYYMMDD.md
                                │
[步驟二：複製明細] ─────> 寫入 data/inbox/IN_YYYYMMDD_details.md
                                │
[步驟三：一鍵對合] ─────> 執行 lab_data_importer.py 進行前綴模糊比對與合併
                                │
                        [寫入 SQLite 本地庫] (無截斷之 FHIR Observation)
                                │
                        [備份至 data/raw/ 並物理刪除 inbox/ 原始檔]
```

### 📥 步驟一：主表複製與建立
1. 登入健康存摺網頁版，進入「其他檢驗資料」或相關表格。
2. 拖曳選取整個表格內容，按 `Ctrl+C` 複製。
3. 在本地電腦建立純文字檔案 `data/inbox/IN_YYYYMMDD.md` (例如 `IN_202X_XX_XX.md`)，並將內容貼上。

### 🔎 步驟二：明細補全複製 (如有截斷項目)
1. 在網頁上，找到名稱或結果值被縮寫為 `...` 的項目。
2. **點擊該項目**（通常會彈出小視窗或展開詳細資訊頁面），此時將能看到完整的英文全名或完整的電泳文字。
3. 拖曳選取該彈出視窗的內容，複製（`Ctrl+C`）。
4. 在本地電腦建立明細對應檔 `data/inbox/IN_YYYYMMDD_details.md` (例如 `IN_202X_XX_XX_details.md`)，將複製的詳細文字貼入其中。
   *明細貼上格式範例：*
   ```
   Beta-2 Microglobulin: 1.83 mg/L
   Electrophoresis: Serum protein electrophoresis reveals no M-spike.
   ```

### ⚙️ 步驟三：一鍵對合與匯入
執行整合匯入腳本：
```bash
python3 utils/lab_data_importer.py IN_YYYYMMDD.md
```
*腳本將會自動偵測是否存在同名的 `_details.md` 檔案，掃描主表包含 `...` 的欄位，並透過前綴匹配完成補全後寫入本地 SQLite。*

### 🧠 AI 模糊對合演算法設計 (Matching Algorithm)

為了讓腳本能夠聰明地將截斷項目與完整明細對齊，腳本採用以下邏輯：

1.  **時間與上下文定錨**：只有相同檢查日期（如 `202X-XX-XX`）的明細才能與主表對齊。
2.  **字首模糊比對 (Prefix Match)**：
    *   移除兩端空白與 `...`，取得待匹配字根（如 `Beta-2 Microglo`）。
    *   在明細檔中搜尋是否有以此字首開頭的完整項目（如 `Beta-2 Microglobulin`）。
    *   若匹配成功，將主表之項目名稱與結果值均以明細檔的完整版覆蓋。
3.  **防錯與容錯提示 (Fail-Safe)**：
    *   若主表偵測到有 `...` 且無對應明細檔，匯入時將在 SQLite 的 `meta_data` 中將該欄位標記為 `{"is_truncated": true}`，並在對話中提示使用者：「*偵測到檢驗項目 X 存在網頁截斷，建議補充明細檔以確保分析精準度。*」

## 🔒 3. 隱私安全與備份規範

為了防範隱私洩漏，本流程剛性執行以下資料生命週期規則：
1.  **雙檔案同步備份**：匯入成功後，`IN_YYYYMMDD.md` 與 `IN_YYYYMMDD_details.md` 必須**同時被複製**到 `data/raw/` 目錄中封存。
2.  **收件夾即時物理清除**：備份完成後，腳本會立即物理刪除 `data/inbox/` 下的這兩個原始檔案。
3.  **Git 剛性阻斷**：`data/inbox/` 與 `data/raw/` 均已在 `.gitignore` 排除，任何真實血液報告均不會洩漏至外部。
